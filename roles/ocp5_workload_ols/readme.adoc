= ocp5_workload_ols - Deploy OpenShift Lightspeed on OpenShift Cluster

== Role overview

* This role installs the OpenShift Lightspeed Operator into an OpenShift cluster.

* Classic OLS is configured from `ocp5_workload_ols_provider` (`maas`, `azure_sp`, `azure_token`, or `openai`). Default is MaaS.

It consists of the following task files:

** Tasks: workload.yaml - Deploys and configures OpenShift Lightspeed.
*** This playbook creates the following OpenShift resources:
**** Namespace (openshift-lightspeed)
**** Operator subscription (if ocp5_workload_ols_install_operator is true)
**** One credential secret and OLSConfig for the selected provider
**** ClusterRoleBindings for lightspeed-operator-query-access

** Tasks: install_ols_operator.yaml - Installs the OLS operator from the redhat-operators catalog (channel stable). The 2.0 operator bundle deploys both the classic assistant controller and the agentic controller, the CRDs, the OTEL collector, Postgres and the console plugin.

** Tasks: setup_azure_token.yaml - Creates an Azure AD child app and service principal (when provider is azure_sp).
*** Creates Azure AD app registration and service principal
*** Adds service principal to Azure AD group for RBAC inheritance
*** Validates token works with Azure OpenAI service
*** Waits for RBAC propagation (30s + retry logic)

** Tasks: remove_workload.yaml - Deletes external resources that survive cluster deletion.
*** Only the Azure child app registration (provider azure_sp).
*** MaaS, Azure token, and OpenAI keys are not created by this role and are not deleted here.

** Tasks: deploy_agentic_ols.yaml - Configures the agentic OLS component (when ocp5_workload_ols_enable_agentic is true).
*** Independent of the classic OLS provider.
*** Requires ocp5_workload_ols_agentic_api_key. Catalogs that want the same token as classic OpenAI can alias that variable in AgnosticV.
*** Creates the reader RBAC (lightspeed-agent service account) and execution RBAC (cluster-admin for the agentic operator service account) that the OLM bundle does not provide.
*** Creates the LLMProvider, Agent (default and smart) and ApprovalPolicy CRs.
*** Creates the alerts-adapter-config ConfigMap; the adapter itself is enabled through spec.ols.deployment.alertsAdapter.configMapRef in the OLSConfig.
*** Optionally points ClusterVersion at the fauxinnati fake update graph (ocp5_workload_ols_agentic_enable_cluster_updates).

== Agentic OLS Configuration

* Set ocp5_workload_ols_enable_agentic: true to configure the agentic component on top of classic OLS. The agentic operator itself is always installed by the operator bundle; this flag adds the LLMProvider/Agent/ApprovalPolicy CRs, the agent RBAC and the alerts adapter configuration.
* Provide ocp5_workload_ols_agentic_api_key. This is independent of classic OLS credentials.
* ocp5_workload_ols_agentic_provider selects the LLM backend: maas (OpenAI-compatible MaaS endpoint, model claude-sonnet-4-6 by default) or openai (direct API key).
* The alerts adapter is enabled through the OLSConfig (spec.ols.deployment.alertsAdapter.configMapRef) and processes alerts routed to the critical receiver, creating AgenticRuns for autonomous investigation.
* The OLSConfig also sets spec.ols.userDataCollection explicitly (feedback and transcript collection enabled).
* Analysis and Execution stages require manual approval (ApprovalPolicy CR); Verification and Escalation run automatically.
* Agentic OLS is not uninstalled on destroy — the cluster itself is deleted.
* Reference: https://docs.redhat.com/en/documentation/red_hat_openshift_lightspeed/2.0/html-single/configure/[Configuring and deploying OpenShift Lightspeed 2.0].

== The defaults variable file

* This file ./defaults/main.yaml contains all the variables you need to define to control the deployment of your workload.
* The variable ocp_username is mandatory to assign the workload to the correct OpenShift user.
* A variable silent=True can be passed to suppress debug messages.
* You can modify any of these default values by adding -e "variable_name=variable_value" to the command line.
